## Summary
On 2025-10-02, 14% of cart-api add-to-cart and update requests failed with
HTTP 500 for 47 minutes. Reads of existing carts kept working. Classified SEV2:
a revenue path degraded within the 5-50% error band.

## Root cause
A new "recently viewed" feature in recommendations-api wrote `reco:*` keys into
the shared redis-cache with no TTL. used_memory grew from 3.1gb to the 6gb
maxmemory over four days. With `maxmemory-policy noeviction`, every write
returned `OOM command not allowed when used memory > 'maxmemory'`, so cart
writes failed while reads succeeded.

## Resolution and follow-ups
Deleted 41M `reco:*` keys with `--scan | UNLINK` in batches; errors stopped
within 3 minutes. Set a 24h TTL on the new keys and changed the policy to
`volatile-lru`. Action item AI-402: alert at 85% of maxmemory. Action item
AI-403: give recommendations-api its own Redis instance.
