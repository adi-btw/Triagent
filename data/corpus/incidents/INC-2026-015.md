## Summary
After v4.2.0 shipped on 2026-06-17, recommendations-api pods were OOMKilled
roughly every 3 hours for two days. During restarts the "You may also like"
widget was empty for about 6% of page views. Classified SEV3: a non-revenue
feature degraded; checkout and cart were unaffected.

## Root cause
v4.2.0 added an in-process dictionary caching per-user feature vectors with no
size bound. Memory per pod grew linearly from 600Mi to the 2Gi limit, then the
kernel killed the container (exit code 137). The leak was confirmed by a
`tracemalloc` snapshot in staging showing the cache as the top allocator.
Startup memory was normal, which distinguished it from a too-low limit.

## Resolution and follow-ups
Rolled back to v4.1.3 with `kubectl rollout undo`; memory stayed flat at
~650Mi. v4.2.1 replaced the dictionary with a bounded LRU (50k entries).
Action item AI-588: alert when memory working set grows more than 20%/hour.
