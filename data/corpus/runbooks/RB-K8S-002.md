title: Latency from CPU throttling
services: [all]

## Symptoms
p95 latency rises (often 2-5x baseline) with no increase in error rate at
first, while average CPU usage looks well below the limit. Readiness probes may
start timing out (`Readiness probe failed: context deadline exceeded`), pulling
pods out of rotation and causing intermittent 503s. Common after lowering CPU
limits or after a traffic increase on a service with tight limits (for
example `cpu: 500m`).

## Diagnosis
1. Throttle ratio per pod:
   `rate(container_cpu_cfs_throttled_periods_total[5m]) /
   rate(container_cpu_cfs_periods_total[5m])`. Above 0.25 is significant.
2. `kubectl get deploy <service> -n prod -o jsonpath='{..resources}'` to read
   requests and limits.
3. Check worker count vs limit: 4 uvicorn workers in a 500m container will be
   throttled under any real load.
4. Rule out the database: if latency is in DB calls, see RB-DB-004 or RB-DB-001.

## Mitigation
- Raise the CPU limit (or remove it and keep a realistic request), then
  `kubectl rollout restart deployment/<service> -n prod`.
- Scale out horizontally if the node pool has headroom.
- Match worker or thread count to the CPU limit.
